# nylai 后续效率能力调研

调研日期：2026-11-10。范围：本地优先的 macOS 效率集合，不引入账号、云服务、root 或驱动。本文是机会评估，不代表已排入开发计划或已经实现。

## 结论

下一轮最值得做的是 **选区 OCR → 剪贴板、命名常用短语、剪贴板多条合并**。三者分别复用现有截图、历史搜索和安全粘贴链路，能减少实际任务中的重复操作，而不是继续增加孤立入口。

再往后考虑 **窗口布局动作、临时文件架和统一动作搜索**。先让现有模块组成连贯流程，再扩展模块数量。系统监控可以补低磁盘空间等少量可行动提醒，但不宜马上发展成完整硬件管理工具。

这里的“高频”是基于任务性质与公开需求的产品判断，**不是用户规模或使用频率统计**。官方 issue 证明有人遇到或提出过需求，不证明所有人普遍遇到，也不据此判断竞品现在仍未修复。

## 现状：哪些已经有，哪些仍缺

依据仓库 README、PRODUCT、DESIGN、需求规格及当前工作区实现：

| 领域 | 已有能力 | 更值得补的缺口 |
|---|---|---|
| 截图 | 选区／窗口捕获、标注、马赛克、滚动截图、拼图、历史、置顶 | 图片文字提取、输出前快速压缩／缩放，以及与剪贴板的衔接 |
| 剪贴板 | 文本／图片历史、搜索、置顶、来源屏蔽、清理、安全直接粘贴 | 命名常用短语、多条文本合并、对当前剪贴板执行明确的转换动作 |
| 快捷键／手势 | 系统功能与应用启动／切换，可按应用配置手势 | 可搜索的动作入口、对已有内容执行动作；避免每加功能就再占一个键位 |
| 窗口 | 应用分组切换、窗口预览和激活 | 移动／调整布局、移到下一显示器、恢复最近一次位置 |
| 系统监控 | CPU、内存、网络、存储，按需采样，菜单栏读数，系统工具入口 | 少量阈值提醒与明确后续动作；不缺更多常驻数字 |
| 文件 | 本轮接入访达右键“新建文件／复制路径／在此打开终端”，真实 Finder 兼容待验收 | 文件模板、常用应用打开及跨窗口临时收集 |

“置顶历史项”不等于“命名模板库”；“已经能粘贴纯文本历史”也不等于“对当前系统剪贴板执行一键去格式”。应在产品文案和验收中区分。

## 公开需求与优秀产品带来的启发

| 一手来源 | 可确认的事实 | 对 nylai 的含义 |
|---|---|---|
| [Maccy #1204：Snippets support](https://github.com/p0deje/Maccy/issues/1204) | 用户明确区分置顶项与可管理的 snippets，举出远程终端复用命令片段的场景；该 issue 被归并到另一需求 | 置顶不是常用文本管理的终点，可先做命名、分组、搜索和手动插入 |
| [Maccy #239：多条粘贴](https://github.com/p0deje/Maccy/issues/239) | 用户希望把多个来源的地址字段等收集后合并粘贴，讨论涉及选择方式与导出历史的隐私边界 | 做明确选择的多条合并，避免“全部历史一键外发” |
| [Maccy #134：文本类型与纯文本粘贴](https://github.com/p0deje/Maccy/issues/134) | 用户提出忽略图片、默认纯文本等工作方式 | 类型筛选与转换应成为动作，不应要求反复进设置改变全局模式 |
| [Espanso #2743](https://github.com/espanso/espanso/issues/2743)、[官方 Secure Input 说明](https://espanso.org/docs/troubleshooting/secure-input/) | 安全输入会影响自动触发文本扩展；issue 请求在运行时提供可执行的替代入口 | 常用短语先做显式搜索／插入；不要首版就监听所有输入或试图绕过安全输入 |
| [Rectangle #1552：跨显示器恢复](https://github.com/rxhanson/Rectangle/issues/1552) | 用户报告窗口移动显示器后恢复位置与尺寸不符合预期，并讨论恢复语义 | 布局需求有价值，但“恢复到原屏幕”还是“在当前屏幕恢复比例”必须先定义 |
| [Shottr 官方功能](https://shottr.cc/)、[官方隐私说明](https://shottr.cc/kb/privacy) | 提供截图文字识别，并说明 OCR 本地处理 | 学习“当前画面 → 文字”的短流程，不必引入在线 AI |
| [Alfred Universal Actions](https://www.alfredapp.com/help/features/universal-actions/) | 从已有文件、文本、链接出发，按内容类型显示动作 | 比再做一个全功能启动器更适合当前项目：先统一已有动作，再按输入类型扩展 |
| [Dropover 官方介绍](https://dropoverapp.com/) | 使用临时架收集文件、文本、链接、图片，再集中移动或处理 | 文件跨应用流转存在独立于长期剪贴板历史的场景；短暂收集、完成即清空可保持轻量 |

这些来源分别覆盖“有人提出的实际问题”与“成熟产品采用的交互”。竞品宣传页只证明该产品提供某种能力，不证明它是所有用户的痛点。

## 八个候选的取舍

下表的成本与稳定性是结合当前代码的工程判断，尚未经过原型计时；“低／中／高”是相对值，不是工期承诺。

| 优先级与候选 | 任务频率／收益判断 | 复用与首版边界 | 成本、权限与稳定性 |
|---|---|---|---|
| **P1 选区 OCR → 剪贴板** | 不能选中的报错、截图、远程桌面文字，需要重新手打；对这类工作收益高 | 复用截图选区与历史，只做“识别并复制”；保留换行／合并行可作为两个明确动作，识别失败不生成空成功记录 | 中；直接用已捕获图片不加权限，跨应用画面仍沿用屏幕录制授权；中文／英文、小字、混排要专项验证 |
| **P1 命名常用短语** | 邮箱、回复模板、地址、终端片段重复输入，适合日常复用 | 从剪贴板“保存为短语”，名称、内容、分组、搜索；首版手动选择插入，至多加日期／剪贴板占位符 | 低至中；复制不需额外权限，直接粘贴沿用现有权限；自动键入触发延后，降低输入法／安全输入兼容负担 |
| **P1 多条剪贴板合并与轻转换** | 多处复制后拼到一段文本，或粘贴时去掉格式，减少来回切换 | 多选后按可见顺序合并；分隔符仅换行／空格；加入当前剪贴板的纯文本动作、去首尾空白。不要一开始加入几十种转换 | 低至中；复用历史模型和粘贴目标校验；首版只合并文本，不混合图片、文件和文本 |
| **P2 窗口布局动作** | 反复调整两窗口对照、跨显示器工作；多窗口用户收益高 | 复用窗口身份和 AX 校验，先做左右半屏、最大化、居中、下一显示器、撤销最近一次布局；统一进入快捷键／手势动作目录 | 中；辅助功能权限；跨屏缩放、最小尺寸、应用拒绝调整是稳定性重点。不要首版做整套桌面恢复 |
| **P2 临时文件架** | 多文件来自不同目录，目标应用暂不可见，拖动中途要切窗口 | 承接 Finder、截图输出与剪贴板图片；用户主动拖入／快捷键打开，一次收集、一并拖出；不自动移动原文件 | 中；优先使用拖放给出的 URL，处理文件被移动／删除；不依赖常驻监视全部文件或自动摇鼠标识别 |
| **P2 统一动作搜索** | 功能增长后记不住快捷键，设置页不是执行入口 | 搜索现有动作、应用绑定、常用短语；支持收藏和最近使用。先不建全盘文件索引，也不做扩展商店 | 中；大部分复用当前动作目录；若读“任意应用的选中文本”再单独验证权限与失败退路，不默认模拟复制来改写剪贴板 |
| **P2 输出图片的轻量准备** | 聊天、工单、网页上传受尺寸／体积限制；截图做完还要另开转换工具 | 在现有输出处增加最长边缩放、PNG／JPEG、体积预估，保留原图；再考虑批量拖入。目标是减少最后一步，不是做通用图片编辑器 | 低至中；现有像素渲染与保存管线可复用；透明度、色彩、Retina 尺寸必须一致，目标大小不能虚假承诺一定达成 |
| **P3 可行动的监控提醒** | 用户不可能一直盯菜单栏；低空间和持续高负载才可能影响工作 | 先做可选低磁盘空间提醒，冷却时间与恢复阈值，提供打开系统存储；CPU 持续超阈值再考虑 | 中；通知权限；提醒开启才后台采样，并控制频率。不要把瞬时 CPU 上升当故障，不做自动清理／强制结束进程 |

OCR 的系统实现入口可以使用 Apple Vision 的 [VNRecognizeTextRequest](https://developer.apple.com/documentation/vision/recognizing-text-in-images)，官方示例直接处理 CGImage；这是可行性依据，具体性能仍需本机验证。

图片准备与内容转换的产品参照可看 [PowerToys Advanced Paste 官方文档](https://learn.microsoft.com/en-us/windows/powertoys/advanced-paste)，其中包含纯文本、文件和本地 OCR 等动作；应借鉴短流程，不复制 Windows 的系统接入方式。

监控提醒的成熟参照是 [iStat Menus 官方通知说明](https://diagnostics.bjango.com/help/istatmenus6/notifications/) 与 [版本记录](https://register.bjango.com/mac/istatmenus/versionhistory/)中的磁盘可用空间提醒。它证明这种产品形态存在，不等于 nylai 现在需要照搬其全部监控范围。

## 系统已经有的能力，不宜简单重复

| 系统原生能力 | nylai 应做的差异 |
|---|---|
| [窗口平铺](https://support.apple.com/guide/mac-help/mchlef287e5d/mac) | 统一快捷键／手势入口、跨屏、明确撤销；不是再增加一个同样的左右平铺按钮 |
| [文字替换](https://support.apple.com/guide/mac-help/mh35735/mac) | 命名分组、搜索、从历史保存、多行模板与明确插入；普通缩写替换优先用系统功能 |
| [预览中的 Live Text](https://support.apple.com/guide/preview/prvw625a5b2c/mac) | 从当前屏幕选区一步识别复制，省去截图落盘、打开预览、选中文字的中转 |
| [Finder 快速操作中的图片转换](https://support.apple.com/guide/mac-help/mchl97ff9142/mac) | 面向截图输出的尺寸／体积准备，而不是只做另一份格式转换菜单 |

## 暂缓的方向

- **全功能启动器／插件商店**：Raycast 的[官方快速入门](https://manual.raycast.com/quickstart)展示了应用、文件、链接、计算、短语、窗口等统一入口；值得学习动作可发现性，但它意味着索引、排序、扩展生命周期等独立产品成本。nylai 先做现有动作搜索即可。
- **完整工作区恢复**：比单窗口布局多出应用启动、多实例对应、文档身份、显示器拓扑等问题。[PowerToys 官方 Workspaces 文档](https://learn.microsoft.com/en-us/windows/powertoys/workspaces)明确提到已有实例可能导致不同应用表现不同；[官方 issue #35918](https://github.com/microsoft/PowerToys/issues/35918)有多实例顺序需求。Windows 案例只作为复杂性参照，不据此推断 macOS API 行为。
- **自动监听输入的文本扩展**：先把手动短语插入做好。安全输入、输入法、目标应用焦点都可能影响可靠性，见上文 Espanso 一手证据。
- **风扇控制／驱动级音量管理／自动清理**：与当前轻量、无 root 的约束不匹配，维护成本和误操作后果更高。若以后有明确需求，单独验证权限、硬件与分发方式，不因竞品有就加入。
- **云端 AI、共享云盘、账号同步**：不是当前定位的自然延伸。先解决本地动作闭环；配置导出／导入可以作为维护能力独立补齐，不必建立账户系统。

## 建议按三轮推进

1. **补已有模块的闭环**：选区 OCR、命名短语、多条文本合并。每个功能先定义一条可重复任务，例如“从远程桌面取错误码并粘贴到搜索框”，记录实际步骤、成功率和权限失败时的退路。
2. **串起窗口与文件流转**：窗口布局动作、临时文件架；在确有多个常用动作后增加统一动作搜索。访达右键本轮单独做接入验证，尤其不能把多选第一项伪装成右键目标。
3. **按真实使用再扩展**：图片输出准备、低磁盘提醒、配置导出／导入。优先看用户一周内反复离开 nylai 去完成什么，而不是比对竞品缺了多少复选框。

每轮只选择 1–2 个明确任务交付，不并行打开八个模块。验证只覆盖受影响模块和真实系统接入点；不默认把每次修改扩大为截图、手势等全量回归。
