# 模块开关、鼠标手势与剪贴板补充规格

更新：2026-11-02。本文新增需求，不代表代码已实现。对应任务见 [补充开发计划](MODULES_GESTURES_CLIPBOARD_PLAN.md)。

原有 [需求规格](REQUIREMENTS.md) 与 [开发计划](DEVELOPMENT_PLAN.md) 继续有效。本文只覆盖模块生命周期、独占交互、鼠标手势和剪贴板；同一问题存在冲突时，以本次确认的补充规则为准。不要重写另一个开发者正在维护的任务状态。

用户已确认的规则直接写入条款；标为「执行默认值」的数值、边界是用于开发的可调整起点。

## 1. 模块启停

### MOD-01 模块范围与默认值

| 模块 | 默认 | 关闭后的结果 |
|---|---|---|
| 截图 | 开启，升级时保留已有状态 | 停用截图、最近截图、拼图入口及对应快捷键／手势目标；关闭已完成的置顶窗口 |
| 全局快捷键 | 开启，升级时保留已有总开关状态 | 释放 nylai 注册的全局键位，保留全部绑定 |
| 鼠标手势 | 关闭 | 不拦截鼠标，不显示轨迹，移除事件 tap、监听和会话 |
| 剪贴板 | 关闭 | 停止读取变化和自动清理，关闭浮动历史面板；保留本地历史与置顶 |

- 设置中统一提供各模块开关，改变后立即应用并持久化。
- 关闭不是卸载或删除数据，不清空配置、不撤销系统权限。重新开启按保存配置恢复。
- 设置入口和退出应用始终可用，不属于可关闭模块。
- 全局快捷键原来的「总开关」与模块开关是同一状态，不能额外增加一套彼此矛盾的总开关；每条绑定的独立开关继续保留。
- 模块设置仍可访问。剪贴板关闭时可在设置中查看、删除、清理旧数据，但不开放记录和浮动历史入口。
- 模块开启意愿与实际状态分开：未授权／启动失败显示具体原因，不能把失败显示成正在运行，也不反复请求授权。

### MOD-02 共享动作与依赖

- 动作执行是共享基础能力，不属于「全局快捷键」模块的私有实现。键盘、鼠标手势和菜单都是动作入口。
- 关闭全局快捷键后，截图仍可从菜单或手势调用；手势的应用切换、发送组合键也可继续工作。
- 目标模块关闭时，所有入口都不得运行其动作。原绑定保留，设置显示「目标模块已关闭」，重新开启后可恢复。
- 键盘入口不继续占用指向已关闭模块的键位；恢复时若被外部占用，显示真实注册失败，不改动绑定。
- 手势目标不可用时保留规则但不接管该规则专属触发；详见 MG-03，不得自动开启目标模块。
- 各模块只管理自己的文件、监听和任务；剪贴板关闭不影响截图复制到系统剪贴板，截图关闭也不禁止记录其他应用复制的图片。
- 截图的「最近截图」与剪贴板历史是两个独立数据集，清空其中一个不删除另一个或用户保存的文件。

### MOD-03 截图独占交互（用户修正规则）

- 截图选择和编辑期间，用户不能同时进入设置或执行其他 nylai 功能；不存在从设置关闭正在编辑截图模块的常规路径。
- 期间屏蔽设置入口、应用切换绑定、鼠标手势、剪贴板浮动面板等交互动作。重复触发截图只回到当前会话，不创建第二个。
- 截图自身的保存面板、颜色选择器和必要权限提示仍可使用。正常完成或取消截图后再恢复其他入口。
- 不锁住整个 macOS，不拦截系统强制退出等系统能力；原规格中系统主动切出后取消截图的恢复规则仍有效。
- 因此不新增「关闭模块前询问保存／放弃／取消编辑」对话框。
- 模块开关只能在空闲交互态更改；若外部状态变更等非常规路径要求停止，统一取消未完成会话并清理，不允许截取或导出新内容。应用退出同样必须释放资源。
- 独占交互只暂停其他交互入口，不等于自动关闭其他模块；已开启剪贴板的轻量后台记录保持其原设置。
- 截图覆盖层不得捕获鼠标手势轨迹或 nylai 其他悬浮界面。

### MOD-04 停止与恢复

- 停止必须幂等：多次停止、停止尚未开始的服务不崩溃；启动不得重复创建监听或计时器。
- 关闭鼠标手势时取消未完成识别、不执行动作；不能遗留鼠标按下状态或吞掉后续正常右键。
- 关闭剪贴板后，已排队读取／解码／写入也不得提交新记录；重新开启用新一代会话，不能让旧任务写回。
- 剪贴板停用时不运行后台清理；手动清理仍可用。重新开启时先按保存策略清理，再建立新的监听基线。
- 开启时只请求该功能实际需要的权限；拒绝不影响其他模块。应用退出后无事件 tap、采集、轮询或悬浮窗口残留。

## 2. 鼠标手势

### MG-01 首批范围

- 按住右键绘制方向路径，松开后触发；支持上、下、左、右及组合，例如 `→`、`↓→`。
- 支持新增／修改／删除规则、启停单条规则、录制路径、绑定动作、轨迹显示开关。
- 首批不做左键／中键重映射、组合鼠标按键、滚轮增强、平滑滚动、触控板手势、屏幕边缘触发或任意图形识别。
- 执行默认值：最多 4 段方向；连续相同方向合并；移动超过 12 屏幕点才进入手势；方向变化需经过最小有效距离，避免抖动生成多余段。阈值集中定义，经真实鼠标验证后调整。
- 执行默认值：轨迹显示开启；只在手势会话显示，松开／取消立即清除；不截获点击，不改变源应用焦点。

### MG-02 与普通右键共存

| 状态 | 松开右键后的行为 |
|---|---|
| 移动未超过阈值 | 产生一次正常右键菜单操作 |
| 已进入手势且匹配有效动作 | 执行一次动作，不弹右键菜单 |
| 已进入手势但无匹配 | 不执行，不弹右键菜单 |
| 手势中按 Esc | 取消，不执行，不弹右键菜单 |
| 模块关闭／所在应用禁用／本次没有有效规则 | 原鼠标事件直接通过，不延迟原生右键 |

- 恢复普通点击的事件必须有来源标记，不能再次被自身识别形成循环，也不能产生重复 down/up。
- 手势期间不吞左键和滚轮。Esc 取消通道只服务当前会话，不记录用户键盘字符。
- 手势开始时确定目标应用、规则作用域与权限状态。执行默认值：中途切换应用或进入截图独占态即取消，不把原动作发送给新应用。
- 事件 tap 超时／被系统停用、睡眠、权限撤销、设备断开或模块停止时终止当前手势，恢复可用的原生输入路径。恢复监听后不补执行旧动作。
- 右键延迟、正常菜单恢复及事件拦截必须先做本机技术验证。仅被动监听无法兑现阻止右键菜单的要求，不可用双触发行为冒充完成。

### MG-03 作用域、冲突与动作

优先级：**应用禁用名单 > 应用专属规则 > 全局规则**。

- 禁用名单内完全不识别、不拦截。
- 按路径查找：当前应用有该路径的专属规则则使用该规则；没有才查全局同路径。
- 同一作用域同一路径不允许重复；不同应用可以为相同路径配置不同动作。
- 专属规则存在但被停用／目标不可用时，不回落执行同路径的全局规则，避免意外动作。
- 一次手势最多执行一个动作。若本作用域及全局都没有有效路径，直接保留原生右键；还有其他有效路径时，进入识别后的无匹配遵循 MG-02。
- 首批动作：调用已实现的 nylai 功能、启动／切换应用、发送一次组合键。
- 应用动作复用之前确认的启动／激活／前台隐藏规则；每条手势中的应用目标也有「前台再次触发隐藏」选项，默认开启。不要求用户先创建全局键盘绑定。
- 发送组合键不是注册全局快捷键，不受全局快捷键模块开关控制。目标为开始手势时的前台应用；权限不足或目标改变时不发送。
- 组合键首批采用已有键码／修饰键模型，不支持宏、连续多键步骤、文本输入或脚本。
- 单纯配置或录制规则不执行绑定动作。录制时使用 nylai 自己的本地录制区域，不修改其他应用。

### MG-04 权限和技术边界

- 优先系统事件 tap 与共享动作执行器；主动拦截及事件发送可能需要系统授权，以技术验证结果为准。
- 只在用户主动开启／使用相关动作时引导必要权限；不能为了仅使用截图或普通键盘绑定就要求鼠标模块权限。
- 不要求管理员、root、驱动或修改系统保护；无法创建所需 tap 时显示未运行并允许正常使用鼠标。
- 过滤回调只做最小的会话判定与事件处理；绘制、识别后的动作、磁盘写入不阻塞回调。

## 3. 剪贴板

### CB-01 内容与记录时机

- 默认关闭，用户开启后记录纯文本与图片；不保留富文本格式，不记录文件引用、文件内容或多媒体。
- 支持浮动历史面板、搜索、复制、置顶及清理；模块关闭后保留设置中的数据管理。
- 执行默认值：在开启、重启恢复、睡眠唤醒时建立当前 changeCount 基线，不补录停用／睡眠前后的现存内容；仅处理后续观察到的变化。
- 执行默认值：开启且唤醒时每 500ms 检查变化；变化后才读取必要内容。快速连续写入可能只观察到最终一项，不承诺捕获系统所有瞬间变化。
- 读取前后校验 changeCount；变化期间不拼接来自不同剪贴板版本的数据。权限拒绝、读取失败、空内容、未支持类型不生成空记录。
- 多项复制按系统条目顺序读取支持项，忽略文件项；同一项同时提供图片和文本时以图片优先，只生成一条。
- 执行默认值：单项文本上限 1 MiB UTF-8；图片编码数据上限 20 MiB、解码前像素上限 4000 万。超限跳过，不先解码巨图再检查；参数集中定义。

### CB-02 数据与去重

- 历史、置顶与配置本地持久化，重启后保留；图片、缩略图和索引都在应用专属目录，不占用剪贴板恢复旧内容。
- 相同内容不新建记录；更新最后复制时间和最新来源，普通记录移到顶部，置顶记录仍在置顶区。
- 执行默认值：文本按原始 Unicode 文本的 UTF-8 内容精确比较，不 trim、不改换行；图片按尺寸及统一像素表示去重，不仅比较不同格式编码后的字节。
- 执行默认值：置顶区按置顶时间倒序，同内容再次复制不改变置顶顺序；普通区按最后复制时间倒序。
- nylai 从历史复制／直接粘贴的回写必须避免监听循环，不生成重复记录，也不自动刷新保留期限；其他应用重新复制相同内容仍正常更新时间。
- 截图复制成功可以被已开启的剪贴板正常记录；它不属于历史面板自己的回写。模块分别去重，不相互复制数据文件。
- 首批不用数据库，采用版本化索引与独立图片文件、原子提交。损坏数据保留恢复线索，不静默全部重置。

### CB-03 数量、自动清理与置顶

- 普通记录默认最多 200 条，可配置；置顶不计入该上限，永不因普通数量或天数自动删除。
- 执行默认值：数量范围 1–5000；保留天数范围 1–365，天数清理默认关闭，启用时初始 30 天。
- 超数量删除最后复制时间最早的普通记录；按天清理同样使用最后复制时间，达到配置时长即过期；两个条件分别执行。
- 启动／开启、成功记录、有效策略变更以及开启期间每小时检查清理；停用或睡眠时不为清理唤醒设备。
- 数字输入在结束编辑或明确提交并校验合法后应用，不在输入「200」的中途以「2」大量删除历史。
- 降低上限后按新上限清理。取消置顶后回到普通记录规则，可能立即被已开启的过期／数量策略清理。
- 「一键清理」只删除所有普通历史，保留置顶；删除置顶或清空全部必须使用明确命名的独立操作。执行默认值：清空包含置顶的全部记录需确认。
- 只删除应用管理的历史文件与索引，不改系统剪贴板当前内容，也不删除用户保存的截图文件。
- 正在进行的解码／记录不能让已经清理的数据重新出现；删除与记录写入必须有顺序一致性。

### CB-04 应用屏蔽与敏感内容

- 提供按应用的禁用名单；加入后不再接收其新复制内容，不自动删既有记录。可从本地应用选择器添加／移除。
- 应用身份使用 bundle ID；在去重与持久化之前先过滤，屏蔽内容不能刷新旧记录的时间或来源。
- 来源只做尽力识别：可读取剪贴板 source 标记并结合观察时前台应用；任一信息命中黑名单即跳过。两者都未知且启用了黑名单时默认跳过。
- **macOS 并不保证每次剪贴板写入都有可信的来源身份；前台应用也不等于实际写入者。不能承诺百分之百屏蔽后台写入或把来源标记当可信安全凭证。**技术验证需明确记录快速切换应用与后台写入的表现。
- 执行默认值：忽略标记为 Concealed、Transient、AutoGenerated 的内容，检查标记后再读取正文；不尝试凭文本内容猜测所有密码。
- 不记录剪贴板正文、图片或按键到日志，不上传；系统剪贴板访问受限时显示实际状态，不反复请求或绕过系统访问控制。

### CB-05 面板、搜索与操作

- 菜单或已配置的快捷键／手势打开历史；执行默认值：新动作不自动分配默认键。
- 搜索匹配文本与来源应用名称，图片仅匹配来源名称，首批不做 OCR；置顶和普通记录都可搜索，仍分组显示。
- 默认点击条目复制并关闭面板；写入失败保留面板，显示原因。置顶、删除等独立操作不误触发复制。
- 执行默认值：方向键选择、Enter 执行默认复制、Esc 关闭；搜索输入不被全局按键录入控件劫持。
- 「直接粘贴回原应用」是独立可选操作。开启面板前记住目标应用，写入所选条目后关闭面板、激活目标、验证前台身份后发送一次粘贴组合键。
- 用户中途选择了其他前台目标、目标退出、权限不足或系统剪贴板已被其他进程改写时，不向其他应用误发粘贴。失败时明确告知，所选内容仍可手动粘贴。
- 不通过直接粘贴默认获取读取历史所不需要的辅助功能权限；仅复制始终是独立基础路径。

## 4. 技术验证与交付顺序

- 本次只增加文档，不调整另一个模型正在执行的任务状态或修改其代码。
- 建议在当前在做的任务结束后接入模块开关，再依次开发鼠标手势与剪贴板；不在任务中途重写共享生命周期。
- 鼠标拦截／普通右键恢复、权限和组合键发送，剪贴板来源归属／访问控制必须先验证，再写完整 UI。
- 所有新模块默认关闭。禁用模块不维持计时器和事件 tap；基础设置与菜单仍可用。
- 每个任务有自动检查及对应人工验收；fake 不能证明真实系统权限、右键菜单或粘贴成功。

## 5. 参考与依据

- [MaxMouse 官方介绍](https://www.better365.com/h-col-204.html)：参考其绘图手势、应用规则和动作配置方向，不把它的所有能力纳入首批。
- [Apple CGEventTapOptions](https://developer.apple.com/documentation/coregraphics/cgeventtapoptions)：被动监听不能修改／丢弃事件，主动过滤才可接管事件；权限以本机验证为准。
- [Apple NSPasteboard changeCount](https://developer.apple.com/documentation/appkit/nspasteboard/changecount)：变化检测依据。
- [Apple NSPasteboard](https://developer.apple.com/documentation/appkit/nspasteboard)：剪贴板读写与访问行为；本机 SDK 中 accessBehavior 标为 macOS 15.4 起，低版本须作可用性分支，不能默认所有系统都允许后台读取。
- [NSPasteboard.org 类型约定](https://nspasteboard.org/)：来源及临时／敏感／自动生成标记是应用间约定，不是保证真实来源的系统认证。
